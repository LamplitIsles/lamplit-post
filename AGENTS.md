# Post implementation guidance

Read `CONTEXT.md` for domain terminology and `contracts/v1/README.md` for the fixed consumer boundary. Standalone authority is FlickNote #4148 and ADR #4149; #4066 is the lightweight behavioral reference. CFL belongs to its own repository. Coordinate public contract changes with the owning Orc.

Use Node 24, npm and package-lock.json. Backend acceptance requires `npm run typecheck`, `npm test`, `npm run build` and `npm run package`; tests prepare the complete artifact. Read `docs/persistence.md` before changing database format, key authentication, transaction boundaries or ownership. One Post process acquires its external key and lease before opening one native SQLite connection. Supported standalone state reopens; foreign/framework state and wrong keys fail before writable initialization. Fresh installations are the only transition path; deployment of existing installations requires a separate operator decision.

One strict Post TOML document owns configuration. Post owns admission, identity pins, sealed credentials, machine tokens, immutable delivery snapshots and send reconciliation. Keep platform I/O outside synchronous SQL transactions. Observation and eligible deliveries commit together. Unknown native submissions stay unresolved without automatic resend; preserve confirmed IDs when archiving fails. Recheck admission for every history/member/media/send operation; opaque IDs grant no authority.

The runtime uses Satori/Cordis public adapter seams and the Matrix account-token SDK. Read `docs/dependencies.md` before changing the exact Matrix timer patch. Shutdown closes intake, cancels and drains actual HTTP/platform/domain I/O, disposes adapters, closes SQLite, then releases ownership. Startup cancellation must retire late listeners and suppress readiness.

Tests own HOME/data/config/key, subprocess groups and platform/receiver endpoints. Use real SDKs against local fixtures; retain private-peer admission, Matrix catchup suppression, ordered literal mention IDs, image preflight, shared full-response/native deadlines and truthful native-handoff receipts. Keep secrets out of config, logs and API errors. Implementation acceptance excludes live services/accounts, installation, deployment and cutover.

Operator artifacts belong in `docs/`, `deploy/` and `examples/`. Evidence belongs under ignored `.scratch/standalone-satori/`; preserve prior ignored archives and never stage scratch. Settings UI and human login are separate product work; keep the backend headless. Merge does not deploy; the current managed unit requires a later explicit operator transition.
